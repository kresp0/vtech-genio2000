# FIRMWARE_API: reusable routines (bank 0)

All entries are 3-byte `JP` in the table `B0:003B-0116` (74 entries, stable even if the internal code changes; **CONFIRMED** that they are in bank 0, always visible). They are called with `CALL addr` from any window. The complete table with first instructions and number of calls is generated by `api_table.py`. The **names are proposals** (convention `fw_*`); confidence level per row.

Observed convention (PROBABLE, from the code pattern): the routines preserve the registers they use (`PUSH AF/BC/DE/HL` on entry, `POP` on exit), returning in `A`/carry. There are no stack parameters.

## Minimal example verified in MAME (EMU, not on hardware): `tools/example-cartridge/hello_api.s`
Source: `hello_api.s`; build with `build.sh` and pad to 16,384 B with 0xFF; run with `tools/analysis/run_cart.sh`
(EMU result: row 0 `       HOLA!`, row 1 `    GENIO 2000!!`).
```asm
        .area   _HEADER (ABS)
        .org    0x8000
        .db     0x55,0xAA,0x59,0x45     ; autostart signature
        jp      start
start:  ld      sp,#0xDFF0
        call    0x05CF                  ; LCD init (NOT API; autostart happens BEFORE 10D5)
        call    0x009B                  ; lcd_clear
        ld      hl,#msg1 ; call 0x00AD  ; centred on row 0
        ld      hl,#msg2 ; call 0x00B0  ; centred on row 1
        ei                              ; the ISR refreshes the LCD from the buffer
loop:   jr loop  ; do NOT use HALT: on the real unit it switches the unit off (HW_RESULTS_20261110)
msg1:   .db 6,'H','O','L','A','!'
msg2:   .db 13,'G','E','N','I','O',' ','2','0','0','0','!','!'
```
**Finding (EMU)**: without `CALL 05CF` the LCD stays uninitialised (the normal start-up does it at `10D5`, *after* the cartridge probe at `1012-1030`) and only partial garbage is seen (`00!!`), even though the RAM buffer `DCA0` is correct (RAM dump: rows 0/1 correct). A cartridge with the `YE` signature receives control with the CPU in `DI`, `SP=DFF0`, no LCD initialised and no working ISR.
